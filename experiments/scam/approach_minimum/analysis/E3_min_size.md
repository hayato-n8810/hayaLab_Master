# E3. 最小集約サイズ分布 — サイズ可変設計の効果

## 1. 目的

提案手法は **サイズ depth (Diff ⊂ Brother ⊂ ExParent ⊂ Parent)** を可変に持つ設計を採用している。 本レポートでは 「**各実装対について、 最小サイズで集約に到達できるか / より広いサイズが必要か / どのサイズでも到達できないか**」 の分布を定量化し、 サイズ可変設計の意義を実データで示す。

paper §結果2 「サイズや抽象度が変わった時のパターンの変化」 (tab:exp-min-size) を新規データで全面差替えする。

**v7 注記**: 三本立て化 (bigram + unigram + excluded) に対応し、 「excluded (cutout が空)」 を新カテゴリとして分離。 主軸 cell は L0/L1 × τ=0.7/0.9 = **4 (τ, level) ペア**。

---

## 2. 用語と定義

| 用語 | 定義 |
|---|---|
| **最小集約サイズ** | ある実装対 mb_id について、 サイズ depth を **Diff → Brother → ExParent → Parent** の順に広げていき、 「そのクラスのメンバ数 ≥ 2」 を満たした最初の depth |
| **none** | 4 つの全 depth でクラスに居るが singleton にとどまった実装対 |
| **excluded** | 4 つの全 depth で cutout が空となり、 集約対象から除外された実装対 |

paper のサイズ設計の包含関係 σ1 ⊂ σ2 ⊂ σ3 ⊂ σ4 と一致する。 「最小集約サイズが Diff」 は最も早く集約に到達したことを意味する。

---

## 3. 入力データ

| 用途 | パス |
|---|---|
| 集約結果 (4 depth × 2 level × 2 τ) | `outputs/scam/approach_minimum/integrate/jaccard{07,09}/level{0,1}/{depth}/{depth}.json` |

各 (τ, level) について、 全 29,809 実装対の最小集約サイズを判定した。

## 4. 結果

### 4.1 (τ, level) ごとの分布

| τ | 抽象化 | Diff | Brother | ExParent | Parent | none | excluded |
|---|---|---:|---:|---:|---:|---:|---:|
| 0.7 | 0 | 69.4 % | 5.4 % | 3.5 % | 2.4 % | **18.8 %** | 0.4 % |
| 0.7 | 1 | **76.8 %** | 5.1 % | 2.7 % | 2.1 % | 12.8 % | 0.4 % |
| 0.9 | 0 | 54.3 % | 7.3 % | 4.3 % | 2.2 % | **31.5 %** | 0.4 % |
| 0.9 | 1 | 61.3 % | 7.1 % | 3.8 % | 2.1 % | 25.3 % | 0.4 % |

(件数表は補足 §A.1 を参照)

### 4.2 観察

#### 4.2.1 「Diff で集約できる事例」 が大半 (54-77 %)

設計次元によって幅があるが、 **最小サイズの Diff で集約に到達する事例が常に過半数**。 抽象化を上げると Diff のみで集約できる事例の割合が単調に増える (例: τ=0.7 で L0 69.4 % → L1 76.8 %)。

#### 4.2.2 「Diff より広いサイズが必要な事例」 が 9-15 % 存在

τ=0.7 L0 では:
- Brother: 5.4 % (1,616 件) — 兄弟ノードを含めて初めて集約に到達
- ExParent: 3.5 % (1,055 件) — 内側ブロックまで広げて初めて集約に到達
- Parent: 2.4 % (716 件) — 外側ブロックまで広げて初めて集約に到達

合計 **11.4 % (3,387 件)** が Diff だけでは集約できず、 兄弟以上を要する。 τ=0.9 ではこの割合は **13.8 % (4,105 件)** に増加。

**この事実は 「サイズを 1 つに固定すると、 ある程度の事例で集約に到達できない」 ことを意味し、 paper の主張 「サイズを設計の軸として可変に持つことの意義」 を直接支持する**。

#### 4.2.3 「none = どの depth でも集約不可」 が一定割合存在

| τ | none の最小 (L1) | none の最大 (L0) |
|---|---:|---:|
| 0.7 | 12.8 % (3,820 件) | 18.8 % (5,592 件) |
| 0.9 | 25.3 % (7,528 件) | 31.5 % (9,403 件) |

none の事例は singleton 4 個分 (全 depth で 1 メンバ)。 paper §6.2 「集約されなかったもの」 として論じる対象。 これらの実装対は 「希少な構造を持つため類似事例が見つからなかった」 もの (詳細は E4 参照)。

#### 4.2.4 「excluded = cutout が空」 は depth に依らず 0.4 % で固定

129 件 (0.4 %) が全 depth で cutout が空 (= 集約対象外)。 これは「事前分析の Stage-B 通過 359 件には一切含まれない」 ことを E4 で確認済み。 構造的に 「最小限のトークン (2 つ以上) を持たない事例」。

#### 4.2.5 抽象化の効果

抽象化レベルを 0 → 1 と上げると **「Diff 集約率」 が上がり 「none 比率」 が下がる**:

| τ=0.7 | Diff | none |
|---|---:|---:|
| L0 | 69.4 % | 18.8 % |
| L1 | 76.8 % | 12.8 % |

抽象化を上げるほど、 表記の差で別物扱いされていた事例が同型化されるため、 最小サイズ Diff でも集約できる事例が増える。

#### 4.2.6 τ の効果

τ=0.7 → 0.9 で Diff 集約率は 15 ポイント減 (一気に厳しくなる)、 none は 13 ポイント増。 「広く集約 vs 純粋分散」 のトレードオフが最小集約サイズの分布にも現れる。

ただし **Brother・ExParent・Parent の割合は τ=0.9 でむしろ増える** (例: Brother は L0 で 5.4 % → 7.3 %)。 これは 「Diff では集約できなくなった事例の一部が、 より広い depth で集約に到達する」 ためで、 サイズ可変設計の意義が τ=0.9 でより顕著になる。

#### 4.2.7 旧 v6 との対比

旧 v6 (空 bigram 強制 Jaccard=1.0 で擬似クラスタ化) では、 空 bigram 事例 135 件 (Diff) も 「1 つの巨大クラスタに集約される」 ため min_size = Diff として記録され、 区別がつかなかった。 v7 では excluded (129 件) として明示分離されるため、 「**集約失敗の正体が透明化された**」 と言える。

旧 v6 数値 (paper の tab:exp-min-size 現状値) との比較:

| 出力 | 旧 v6 (τ=0.7 L0) | 新 v7 (τ=0.7 L0) |
|---|---|---|
| Diff | 70.3 % (空 bigram 1,487 件含む) | 69.4 % + excluded 0.4 % |
| Brother | 5.4 % | 5.4 % |
| none | 18.6 % | 18.8 % |

数値上の差は小さいが、 解釈の精度が上がっている。

## 5. 考察

### 5.1 paper の主張への寄与

E3 の数値は paper §結果2 の主張 「**サイズを可変にすることで段階的に集約できる**」 を以下の点で支える:

1. **大多数の事例 (54-77 %) は最小サイズで集約できる** — シンプルな設計で十分なケースが多い
2. **9-15 % の事例はより広いサイズが必要** — サイズ可変性の必須性を定量的に裏付け
3. **13-32 % の事例はどの depth でも集約に至らない** — 自動化の限界 (E4 で分析)
4. **0.4 % の事例は cutout が空で集約対象外** — 構造的に最小トークン未満の事例
5. **抽象化を上げると Diff 集約率が増え、 none が減る** — 抽象化とサイズの相互作用

### 5.2 「サイズ単一固定」 では何が失われるか

paper §結果2 で 「**もし Diff のみに固定したら、 τ=0.7 L0 で 11.4 % (3,387 件) の事例は集約に到達できない**」 と書ける。 これは事例総数 29,809 のうちの **約 1/9** に相当する。

3,387 件のうち:
- Brother で初めて集約に到達: 1,616 件 (= 兄弟ノードのコンテキストが必要、 例: pattern 2 substr の `!==` 比較構造)
- ExParent で初めて到達: 1,055 件 (= 内側ブロックの構造が必要、 例: pattern 9 高階関数の呼び出し全体)
- Parent で初めて到達: 716 件 (= 外側ブロック (関数全体) の構造が必要、 例: pattern 1 for-in ループの全体)

E1 §4.7 で見た 「pattern 1 は Parent、 pattern 9 は ExParent が個別最適」 という結論が、 E3 の集計では **「Parent で初めて集約に到達する 716 件」** と **「ExParent で初めて集約に到達する 1,055 件」** という形で具体的に現れる。

### 5.3 「none」 と 「excluded」 の区別 (E4 への接続)

旧 v6 では excluded を区別せず、 「集約失敗 = none」 として一括していた。 v7 では:

- **excluded (129 件)**: cutout が空、 そもそも集約対象外。 paper §6.4 妥当性脅威で 「最小限の構造を持たない事例」 として明記
- **none (12.8-31.5 %)**: 全 depth で singleton。 希少な構造を持つため類似事例が見つからなかった事例 (E4 で詳細)

両者は対照的: excluded は構造の不在、 none は構造の希少性に由来。

### 6.3 文章ドラフト (約 600 字)

> 表 \ref{tab:exp-min-size} に、 各実装対の最小集約サイズの分布を示す。 サイズ depth を差分のみ (σ1)、 兄弟まで (σ2)、 内側ブロックまで (σ3)、 外側ブロックまで (σ4) の順に広げ、 そのクラスのメンバ数が 2 以上となった最初のサイズを 「最小集約サイズ」 とした。 加えて、 4 つの全 depth で cutout が空となる事例は 「対象外」 として分離した。
>
> 類似度閾値 τ=0.7、 抽象化レベル 0 のもとでは、 29,809 件の事例の 69.4 % が差分のみ (σ1) で集約に到達した。 兄弟まで広げて初めて集約に到達する事例は 5.4 % (1,616 件)、 内側ブロックまで広げて初めて到達する事例は 3.5 % (1,055 件)、 外側ブロックまで広げて初めて到達する事例は 2.4 % (716 件) であった。 一方で **どのサイズでも集約に到達できなかった事例が 18.8 % (5,592 件) 残った**。 また cutout が空となり対象外となる事例が 0.4 % (129 件) 存在した。
>
> 抽象化レベルを上げると差分のみで集約できる事例の割合が単調に増え、 L1 では 76.8 % となる。 類似度閾値を 0.9 に引き上げると、 差分のみで集約に到達する事例は 54 % に低下し、 集約不可は 32 % まで増加する。 一方で兄弟以上を要する事例の絶対割合 (例: 兄弟まで) は 5.4 % → 7.3 % と増加する。 これは **「閾値を厳しくすると差分のみでは集約できなくなる事例が、 より広い文脈を取り込むことで集約に到達する」** ことを意味し、 サイズを設計次元として可変に保持することの実証的根拠となる。

### 6.4 考察セクションへの接続

- §6.2 「クラス数と集約されなかったもの」: 「集約不可」 (none) の 13-32 % を E4 で「希少構造を持つ事例」 として分析
- §6.3.1 「サイズ・抽象度の組合せとパターンの関係」: 本表の数値が 「抽象化を上げると Diff 集約率が増える」 という単調性を示す材料
- §6.4 妥当性の脅威: 「対象外」 (excluded、 129 件、 0.4 %) について 「最小限の構造を持たない事例は提案手法の対象外」 と明記
