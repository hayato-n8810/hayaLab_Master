# E2. 出力規模グリッド — 集約結果の全体統計

## 1. 目的

設計次元 (類似度閾値 τ × 抽象化レベル × サイズ depth) のグリッドで、 集約結果の規模・分布・偏りがどう変化するかを定量化する。 paper §結果1 「集約されたクラスの統計情報」 (tab:exp-tau) を新規データで全面差替えする。

**v7 注記**: 主軸 cell を **L0/L1 × τ=0.7/0.9 × 4 depth = 16 cell** に限定 (L2/L3 は paper 言及なし)。 三本立て集約 (bigram M2 + unigram U1 + excluded) に対応した内訳列を追加。

---

## 2. 用語と指標

| 指標 | 定義 |
|---|---|
| **クラス数** | 提案手法が生成したクラスの総数 (= bigram クラス + unigram クラス) |
| **M2 (bigram) クラス数** | bigram Jaccard 集約で生まれたクラス (`L*_M2_*`) |
| **U1 (unigram) クラス数** | 1 トークン事例の完全一致集約で生まれたクラス (`L*_U1_*`) |
| **bigram 事例数** | bigram Jaccard 集約の対象 (n_t ≥ 2) |
| **unigram 事例数** | 1 トークン事例 (0 < n_t < 2)、 unigram で集約 |
| **excluded** | cutout が空 (n_t = 0) の事例。 出力対象外 |
| **単独率** (isolated_ratio) | メンバ 1 件のみのクラスが、 集約対象事例 (bigram + unigram) に占める割合 |
| **最大占有率** | 最大クラスサイズ ÷ 集約対象事例数 |
| **集約率** | (集約対象事例数 - 単独件数) ÷ 集約対象事例数 |

### 4.3 設計次元別の傾向

#### 4.3.1 τ (類似度閾値) の効果

|  | τ=0.7 (集約密度) | τ=0.9 (純度) |
|---|---|---|
| クラス数 (L0/Diff) | 13,111 | 18,006 (+37%) |
| 単独率 | 21-32% | 36-46% |
| 集約率 | 68-79% | 55-64% |
| 最大占有率 範囲 | 3.3-11.3% | 0.5-1.0% |
| 最大クラスサイズ 範囲 | 989-3,356 | 151-291 |

→ τ を上げると **クラス数は約 30-40 % 増、 単独率は約 1.4 倍、 集約率は 10-15 ポイント減**。 最大占有率は劇的に小さくなる (3 倍以上の差)。 三本立て化により旧 v6 の巨大擬似クラスタ (1,487 件) は消滅し、 τ=0.9 で最大クラスサイズが 151 まで縮小したのは特に注目に値する。

#### 4.3.2 抽象化レベルの効果 (Diff 固定)

| τ \ 抽象化 | L0 | L1 |
|---|---:|---:|
| 0.7 | 13,111 | 10,385 (-21%) |
| 0.9 | 18,006 | 15,856 (-12%) |

→ **L0 → L1 で 12-21 % 減**。 L1 (リテラル抽象化: 数値/文字列/正規表現を `$n/$s/$r` に置換) は集約に寄与する。

#### 4.3.3 サイズ depth の効果 (L0 固定)

| τ \ depth | Diff | Brother | ExParent | Parent |
|---|---:|---:|---:|---:|
| 0.7 | 13,111 | 14,127 | 12,741 | 13,424 |
| 0.9 | 18,006 | 18,276 | 17,800 | 18,188 |

→ クラス数の順は **ExParent ≤ Diff < Parent < Brother**。 Brother は兄弟ノードを含むため特徴量空間が広がり区別が増すが、 ExParent はブロック内側まで取り込むため統合が進む。 ただしどの depth でも差は 12 % 以内で限定的。

ただし **最大クラスサイズには大きな差がある** (τ=0.7 L0): Diff 1,031 / Brother 989 / ExParent 984 / Parent 1,909、 τ=0.7 L1 では Parent が 3,356 まで膨らむ。 Parent は範囲が広いため、 巨大クラスタが発生しやすい。

#### 4.3.4 旧 v6 との対比 — 巨大擬似クラスタ問題の解消

| 集計値 | 旧 v6 (空 bigram 強制 Jaccard=1.0) | 新 v7 (三本立て) |
|---|---|---|
| τ=0.7 L0 Diff の最大クラスサイズ | **1,487** (`L0_M2_9c43d97c`、 既知由来 0 件) | 1,031 (`L0_M2_bd5d5c65`、 内容は要確認) |
| τ=0.9 L0 Diff の最大クラスサイズ | **1,487** (同じ擬似クラスタが残存) | **291** (劇的な縮小、 純粋分散戦略が機能) |
| τ=0.9 L0 Parent の最大クラスサイズ | 151 | **151** (Parent では旧から変化なし) |

τ=0.9 / L0 / Diff の最大クラスサイズが **1,487 → 291 へ (約 1/5 に縮小)** は、 三本立て化の最も大きな効果。 旧では 「τ を上げても巨大擬似クラスタは粉砕されない」 という問題があったが、 v7 では空 bigram 事例が excluded に分離されたため、 純粋分散戦略が完全に機能する。

## 5. 考察

### 5.1 paper の主張への寄与

E2 の数値は paper の主張 「**設計次元によって出力規模と粒度が体系的に変わる**」 を以下のように支える:

1. **τ の効果が最も大きい**: クラス数 +30-40 %、 単独率 +1.4 倍、 最大占有率は 3 倍以上の差
2. **抽象化は L0 → L1 で集約進む** (-12-21 %)
3. **サイズ depth の影響は限定的** (12 % 以内) だが、 最大クラスサイズには影響あり (Parent で巨大化傾向)
4. **三本立て化により旧 v6 の擬似クラスタ問題は解消** (τ=0.9 で最大サイズが 1,487 → 291)
5. **サイズと unigram 事例数は反比例**: Diff で 1,352 件 → Parent で 0 件

### 5.2 「ちょうどよい設定」 の定量基準

| 主張軸 | 推奨設定 | 根拠 |
|---|---|---|
| 「広く集約できる」 | τ=0.7 / 抽象化 1 / Diff | クラス数 10,385、 集約率 77.2 %、 max_share 4.2 % |
| 「純粋に分けられる」 | τ=0.9 / 抽象化 0 / ExParent (or Parent) | 単独率 43%、 max_share 0.5 % (最小)、 ≥100 クラスが 1 個のみ |
| 「網羅的に評価する」 | 16 cell すべて | 本グリッド全体 |

### 5.3 限界点

- **τ=0.7 L1 Parent の最大クラス 3,356 件 (11.3 %)** は relatively 大きい。 Parent は範囲が広いゆえ統合が進みすぎるリスクがある
- 「**抽象化を上げる効果が L0 → L1 で確認できた**」 は paper の主張に貢献するが、 「**さらに上の抽象化 (L2, L3) はどうか**」 は本タスクのスコープ外 (paper §6.3.1 でも論じない)

### 6.4 文章ドラフト (約 600 字)

> 表 \ref{tab:exp-tau} に、 全 16 設計組合せ (類似度閾値 τ × 抽象化レベル × サイズ depth) における集約結果の全体統計を示す。 また 29,809 件の事例は、 表 \ref{tab:exp-tribreakdown} のように bigram 集合を作れる事例、 1 トークンのみの事例、 cutout が空となる事例の三系統に分かれ、 前者は bigram Jaccard で、 中者は完全一致で集約、 後者は集約対象外とした。
>
> 類似度閾値 τ の効果が最も大きい。 τ=0.7 では平均クラス数 11,900、 集約率 73 % が達成され、 τ=0.9 では平均 16,800 まで増加し集約率は 60 % に低下する。 一方で最大占有率は τ=0.7 で 3-11 %、 τ=0.9 では 0.5-1.0 % に収まり、 τ=0.9 が 「多数の純粋クラスへ分散させる戦略」 であることがわかる。
>
> 抽象化レベルを 0 から 1 へ上げる (リテラル値を `$n/$s/$r` に抽象化) と、 クラス数は 12-21 % 減少し集約が進む。 サイズ depth による効果は 12 % 以内と相対的に限定的だが、 最大クラスサイズには影響があり、 サイズ Parent (外側ブロックまで) では集約が進みすぎて最大クラスが 1,909 件 (L0 τ=0.7) や 3,356 件 (L1 τ=0.7) になる場合がある。
>
> サイズ depth と unigram 事例数は反比例の関係にあり、 サイズを広げるほど 2 トークン以上が確保されて bigram 集合が作れる事例が増える (Diff で 1,352 件 → Parent で 0 件)。 一方 excluded (cutout が空の事例) は depth に依らず約 130 件で安定する。

### 6.5 考察セクションへの接続

- §6.2 「自動作成されたパターンは低速な要因を捉えているか」: τ=0.7 と τ=0.9 を 「広く集約 vs 純粋分散」 として対比 (E1 と整合)
- §6.2 「クラス数と集約されなかったもの」: 単独率 (τ=0.7 で 21-32 %、 τ=0.9 で 36-46 %) を 「自動化の境界」 として論じる (E4 と接続)
- §6.3.1 「サイズ・抽象度の組合せとパターンの関係」: 本グリッドの数値で 「設計次元の中で τ が支配的、 抽象化が次点、 サイズの寄与は限定的」 という三段階構造を提示
