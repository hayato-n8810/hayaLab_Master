# RQ1: 既知の高速化パターンは設計空間のどこで、どの程度まとまったクラスタとして捉えられるか

本ドキュメントは、SCAM2026 投稿論文の RQ1 を、事後 F1 最大選択（オラクル）に依存しない
Recall マトリクスへ再設計し、さらにクラスタ同定を**字句署名から matcher（構造）同定へ切り替えた**
最終版の、背景・目的・実験内容・結果・考察をまとめたものである。
実装は `build_rq1_matrix.py`（同定モジュール `identify_matcher.py`）、出力は
`rq1_matrix.csv` / `rq1_matrix.tex`、比較用に `rq1_matrix_lexical.csv` / `rq1_matrix_matcher.csv`。

---

## 1. 背景

### 1.1 旧 RQ1 の問題

旧 RQ1（旧 Table II「F1 上位 2 クラスタ」）は、各パターン `p` について **正解集合 `G_p` に対する
F1 が最大となるクラスタ `C*` を事後選択**して報告していた。これは (a) どのクラスタを `p` とみなすか、
(b) どの設定を見せるか、の両方を `G_p` で選ぶ二重のオラクルであり、性能主張としては致命的に弱い。

### 1.2 改訂はじめにとの関係

改訂版「はじめに」は本研究を「マイクロベンチマーク Web サービスをデータ源として扱う手順を設計し、
その特性を実証的に明らかにする探索的研究」と位置づけ、限界 L1（AST 差分が必ずしも性能差の真因と
一致しない）、L2（低速は相対的で同じ片が両側に現れうる）を明示する。RQ1 は「最良設定の性能」ではなく
「設計空間のどこで・どの程度パターンが立ち上がるか」のマッピングであるべきである。

---

## 2. 目的

> 既知の高速化パターンは、設計空間（サイズ σ・抽象化 α・閾値 τ）のどこで、どの程度まとまった
> クラスタとして捉えられるか。また、必要な設計条件はパターンの構造的性質とどう対応するか。

(i) F1 最大オラクルの排除、(ii) 全 16 設計条件の記述的提示、(iii) 低 Precision の L2 への帰属。

---

## 3. 実験内容

### 3.1 データと設定軸

- 正解集合 `G_p`: 事前分析で **diff-link された（条件 (i) かつ (ii)）** 実装対。`|G_p|` = {P1:36, P2:6,
  P3:20, P6:184, P7:2, P8:2, P9:45}。
- 設計空間: τ∈{0.7,0.9} × α∈{α0,α1} × σ∈{σ1(Diff),σ2(Brother),σ3(ExParent),σ4(Parent)} の全 16 条件。
  包含関係は Diff ⊆ Brother ⊆ ExParent ⊆ Parent（σ3=ExParent が最小の囲みブロック、σ4=Parent が外側ブロックを含む）。
- ID 対応: 事前分析の `mb_id` = `MBDiff.json` の `id` = cutouts / クラスタ数値 prefix。直接突合可能。

### 3.2 同定方式: matcher を cut 部分木に適用（構造同定）

クラスタの同定に `G_p` を使わない。**字句署名 `π_p`（代表値トークンの包含）から、構造同定へ切り替えた**。
各クラスタの代表値が持つ pair id の当該 depth の cut（部分木）に対し、事前分析（`slow_patterns/`）と
**同一の matcher を検出ロジック無改変で適用**し、変更前構造が cut 内に存在するかで同定する
（Stage A のみ＝変更前構造の有無。`is_base_covered`/Stage B の diff フィルタは使わない）。

**cut 部分木への無改変対応（`identify_matcher.py`）**: `ast_nav` は `nodes[idx].parent`
（root からの祖先 full-tree インデックスのパス）と「リスト位置 idx」の一致を前提に子を辿る
（`walk_pre` は単なる `range(len)`）。cut ノードは `origin_index` と full parent パスを保持するので、
**「リスト位置 = origin_index のスパース配列」**を組み、欠損位置を placeholder
（`name="__absent__"`, `parent=[-1]` センチネル）で埋めれば matcher を無改変で流せる。placeholder は
実ノードの親パス（全て ≥0）と一致せず候補名にも一致しないため、子探索・検出のいずれにも拾われない。
cut の外のノードは「存在しない」ものとして扱われ、cut が捉えた範囲のみで構造判定される。

matcher は具体ノード（`value`/`name`）で判定するため**同定は抽象化レベル α に依存せず**、
結果は (pair id, depth) のみで決まる（α は所属クラスタ・代表 pair の違いを通じてのみ結果に影響）。

### 3.3 指標

- `R∪`（recall_noniso, 局所化）: `π_p` を満たす非孤立クラスタの**和集合**に対する Recall。
- `R_max`（recall_best, 集約のまとまり）: `π_p` を満たす**最大の単一クラスタ**に対する Recall。
- Precision は補助（`G_p` が下限のため純度として解釈しない）。各セル `R∪/R_max`、`--` は π_p 充足クラスタ無し。

### 3.4 妥当性検証（adapter が正しく cut だけを見ているか）

既知 G_p ペアで抜き取り検証した。P1/P3 は全 depth で検出。P8(20055,20343) と P6(1347,1603) は
σ1/σ2 で非検出・σ3/σ4 で検出（二項式/連鎖が diff-only cut に揃わないため）。P9(807) は全 depth 非検出
だが、これは ExParent cut にも `reduce` が含まれず（diff 箇所が indexOf/push 側）、adapter のバグではなく
cut が構造を含まないことを確認した。すなわち matcher 同定は「cut が実際に捉えた構造」を忠実に測る。

主な観察:

- **全 7 パターンが局所化される**（少なくとも一設定で `R∪>0`）。
- **局所パターンは σ1 最良**: P1(0.86/0.67), P3(0.95/0.65), P2(0.67/0.33), P9(0.60/0.16) は τ0.7・σ1 で最大。

- **P7(toString.call)** は σ1/σ2 で R∪=R_max=0.50（ただし |G_p|=2）。
- **P9** は R∪ 最大 0.69(σ4) だが R_max ≤0.16 で、reduce/map/forEach の多実現形ゆえ複数クラスタに分散。
- **α は同定に非依存**（matcher は具体ノード）。α の影響はクラスタリング粒度・代表値表示のみ
  （例：P6 σ1 で α0=0.14 vs α1=0.07）。
- **τ=0.9** は閾値が厳しく全体に低下。

低 Precision と L2（τ0.7・σ1）:

- P1 precision(R∪)=0.16, P3=0.21, P9=0.17。低い理由は `G_p` が下限であるため。
- `π_p` 同定クラスタの偽陽性のうち no_diff_linked（条件(i)のみ）の割合: **P1=50%, P3=42%, P9=56%**。
  → L2 の顕在化（同型構造が比較対象でない実装対にも現れる）。
- 構造同定の副次効果: 連鎖を要する P6 は precision が広いスコープで高く（σ4 で 0.78、最大単一クラスタで 0.96）、
  字句同定（トークン共起のみ）で紛れ込む偽陽性を抑制する。

## 5. 考察

### 5.1 設計次元とパターン構造の対応（matcher 同定で明確化）

- **σ（スコープ）= 構造的局所性**: 変更前構造が差分ノード近傍の単一の呼び出し・式に収まるパターン
  （P1 for-in, P3 String(), P2 substr, P9 reduce 単体）は σ1 で最良。連鎖・二項式にまたがるパターン
  （P6 split().join(), P8 n%2）は σ1 では cut に構造が揃わず、σ3/σ4 で初めて立ち上がる。逆に局所パターンは
  σ4 へ広げると R_max≈0 へ崩れ、異なる要因の実装対と混在する。**単一の最良設定は存在しない**。
- **α（抽象化）= クラスタリング粒度・代表値表示**: matcher 同定は α 非依存。α は所属クラスタ・代表 pair を
  変えて R∪/R_max を変動させ、代表値の具体性（P2 `substr 0 1` vs `substr $n0 $n1`）を切り替える。
- **τ（閾値）= 集約の強さ**: 0.7→0.9 で全体低下（細分化）。本データセットでは τ=0.7 が優位。

### 5.1b スコープ拡大に伴う非本質ノードの混入（scope_noise.py）

スコープを広げるとパターンを取り込める一方、変更前構造と無関係な周辺ノードも切り出しコード片に混入し、
代表値の可読性を下げる。全実装対で「切り出しコード片の named ノードのうち差分ノード由来でない割合
（非差分ノード比率）」の中央値を求めると、σ1=0.00、σ2=0.23、σ3=0.36、σ4=0.54 と単調に増加する
（切り出しノード数の中央値も 26→43→46→64）。σ4 では片の半分以上が無関係ノードである。
具体例として P6 規範形クラスタの代表値は σ1 で `$v0 split reverse join`（簡潔）だが、σ3 では
`var $v0 = wordswithoutdots var $v1 = $v0 split join` と変数宣言や偶発的識別子を含む。
この可読性低下は R∪/R_max では捉えられないコストであり、構造が局所に収まるパターンでは σ1 を選ぶ根拠となる。
出力は `scope_noise.csv`。

### 5.2 字句同定からの変化（研究倫理上の正直な報告）

字句署名 `π_p`（トークン包含）から matcher（構造）同定へ切り替えた結果、数値が有意に変化した。

- **不変（構造＝字句が一致）**: P1, P3 は σ1 で 0.86/0.67, 0.95/0.65 のまま。
- **改善（字句では誤選択していた最大クラスタを構造同定が正す）**: P2 R_max 0.00→0.33、P7 R_max 0.00→0.50。
- **低下（字句はトークン在で過大評価していた）**: **P6 σ1 0.76/0.51→0.14/0.03**、**P8 σ1 1.00/0.00→0.00/0.00**。
  これは σ1（diff-only）cut が split().join() 連鎖や n%2 二項式の**構造**を含まず、トークンだけが
  現れていたため。matcher 同定はこれを正しく弾き、構造が揃う σ3/σ4 で検出する。
- **旧 F1 最大表との関係**: 局所パターン（P1,P3）は旧表値を再現するが、**P6/P8 は再現しない**。
  旧表（および字句版）の σ1 における P6/P8 の高値は、構造ではなくトークン共起に由来していたことが判明した。
  よって「オラクル無しで旧 F1 表を再現する」という主張は P1/P3 に限り成立し、P6/P8 には当てはまらない。

この変化はデータ源の特性に忠実な、より厳密な結果である。すなわち「σ1 が大半のパターンに最良」という
字句版の見かけは過大評価であり、正しくは「σ1 は構造が局所に収まるパターンにのみ最良で、連鎖・二項式は
広いスコープを要する」である。

### 5.3 限界の担当

- **L2（相対的な低速）**: 本 RQ1 が主に扱う。低 Precision と no_diff_linked 混入率（P1=50%,P3=42%,P9=56%）で定量化。
- **L1（差分≠真因）**: 差分起点の切り出し手順に内在し Recall では切り分けられない。RQ2 および考察・脅威で扱う。


（新 Table II）。`main.tex` の `tab:exp-pattern-best` に対応。`identify_matcher.py` は PreAnalysis の
matcher を import のみ・無改変で使用する。
